# Unity 하네스

Unity 에셋과 씬을 변경하는 모든 작업에 적용한다. 반복적인 검증 절차는 [UNITY_VERIFY.md](../skills/UNITY_VERIFY.md)를 따른다.

## 영속되는 변경은 에셋에 저장한다

- 씬의 오브젝트 배치, 계층 구조, 컴포넌트 추가·제거, 인스펙터 값, 조명·카메라·콜라이더 설정처럼 영속돼야 하는 결과는 실제 `.unity` 씬 또는 `.prefab` 에셋에 저장한다.
- `Awake`, `Start` 등의 런타임 코드로 씬을 조립하거나 값을 덮어써서 에셋 변경을 대신하지 않는다. Play Mode에서 생긴 변경은 기본적으로 종료 시 사라진다.
- Play Mode는 동작 확인용이다. 확인 뒤에도 남아야 하는 변경은 Edit Mode에서 에셋에 반영됐는지 확인한다.
- 예외적으로 절차적 생성, 저장 데이터 복원, 매치 중 일회성 효과처럼 런타임 상태가 본질인 경우에만 코드로 생성한다. 이 경우에도 기준 상태와 생성 책임을 스크립트에 명확히 둔다.

## 씬과 프리팹의 역할

- 특정 장소에만 필요한 배치·연출·참조는 씬에 둔다.
- 여러 씬에서 재사용하거나 동일한 구성이 반복되는 오브젝트는 프리팹으로 만든다.
- 개발 실험은 우선 `Assets/Scenes/_Development/Dev_Gameplay.unity`에서 한다. 실제 콘텐츠는 `Assets/Scenes/Rooms/` 아래에 `Room_01.unity`처럼 ROOM 단위 씬으로 둔다.
- 해당 ROOM과 무관한 변경으로 콘텐츠 씬을 어지럽히지 않는다.
- 씬을 추가·이름 변경·삭제하면 씬 레지스트리가 있는 경우 이를 함께 갱신하고, Build Settings 등록 여부도 검토한다.

## 참조와 초기 상태

- 씬 내의 고정된 의존성은 가능한 한 직렬화된 참조로 연결한다. 이름·태그 검색을 런타임 초기화 수단으로 남용하지 않는다.
- 코드에서 사용할 태그·레이어·씬 이름은 `Assets/Scripts/Values/`의 상수로 관리한다. Project Settings에 추가·변경하면 대응 상수도 같은 작업에서 갱신한다.
- 씬을 열었을 때 계층 구조와 인스펙터만으로 기본 상태를 파악할 수 있게 유지한다.
- 씬의 기본 상태를 만들기 위한 임시 부트스트랩 코드나 테스트 전용 오브젝트는 완료 후 제거하거나 개발 씬으로 한정한다.

## 안전한 변경과 확인

- `.unity`, `.prefab`, `.asset`과 대응 `.meta` 파일은 함께 관리한다.
- Unity가 생성한 참조 ID를 깨뜨릴 수 있으므로 씬·프리팹 YAML을 무분별하게 직접 편집하지 않는다. 자동 변경이 필요하면 변경 범위를 좁히고 Unity Editor에서 참조·직렬화 오류를 확인한다.
- 씬·프리팹을 변경한 뒤에는 대상 에셋을 다시 열어 계층, 누락된 참조, 컴포넌트 경고를 확인한다.
- Play Mode 검증 뒤 종료한 다음에도 의도한 에셋 변경이 남았는지 Git diff 또는 Inspector에서 확인한다.
