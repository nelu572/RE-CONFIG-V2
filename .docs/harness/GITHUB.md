# GitHub 하네스

GitHub에서의 협업 규칙과 라벨 체계를 정의한다. 커밋·push·PR·이슈 생성은 사용자가 명시적으로 요청한 경우에만 수행한다.

## PR과 이슈

- PR 생성의 상세 절차는 [AUTO_PR.md](../skills/AUTO_PR.md)를 따른다.
- PR에는 담당자(Assignees)를 반드시 지정한다.
- GitHub 이슈는 자주 만드는 작업 단위가 아니다. 사용자가 이슈 생성을 명시적으로 요청할 때만 간결하게 만든다.
- 라벨 생성·이름 변경·삭제는 사용자의 명시 요청이 있어야 한다. 존재하지 않는 라벨을 작업 중 자동 생성하지 않는다.

## 병합 뒤 브랜치 정리

- PR이 병합되면 원격 head 브랜치를 기본적으로 삭제한다.
- 삭제 전에는 PR이 실제로 `MERGED` 상태인지, 해당 브랜치를 base로 하는 열린 PR이 없는지 확인한다.
- 사용자가 유지하라고 한 브랜치와 다른 열린 PR의 base 브랜치는 삭제하지 않는다. 스택 PR에서는 자식 PR이 모두 병합된 뒤에만 부모 브랜치를 정리한다.
- 현재 체크아웃된 로컬 브랜치는 병합 직후 삭제하지 않는다. 안전한 브랜치로 이동한 뒤, 병합된 PR의 head 브랜치인 경우에만 로컬 브랜치도 함께 정리한다.
- `main` 등 기본·보호 브랜치와 PR head가 아닌 브랜치는 이 절차로 삭제하지 않는다.

## 라벨 선택

PR과 필요한 이슈에는 변경 유형 라벨 하나와 관련 영역 라벨만 붙인다. 라벨은 검색·분류용이며, 현재 릴리스 버전 계산에는 사용하지 않는다.

### 변경 유형

| 라벨 | 용도 | 색상 |
| --- | --- | --- |
| `type:feature` | 신규 기능·콘텐츠 | `#16A34A` |
| `type:fix` | 오류·회귀 수정 | `#DC2626` |
| `type:improve` | 기존 동작 또는 사용성 개선 | `#D97706` |
| `type:refactor` | 동작 변경 없는 구조 개선 | `#7E22CE` |
| `type:design` | UI, 연출, 아트 설계 | `#2563EB` |
| `type:docs` | 문서와 기획 색인 | `#0284C7` |
| `type:test` | 테스트·검증 환경 | `#0F766E` |
| `type:chore` | 빌드, 패키지, 저장소 설정 | `#475569` |

### 게임 영역

| 라벨 | 적용 범위 | 색상 |
| --- | --- | --- |
| `area:gameplay` | 이동, 점프, 물리, 상호작용 | `#059669` |
| `area:rules` | SETTINGS와 월드 규칙의 연결 | `#7C3AED` |
| `area:room` | ROOM 씬 구성과 전환 | `#EA580C` |
| `area:gimmick` | 스피커, 피스톤, 벽 등 재사용 기믹 | `#CA8A04` |
| `area:input` | Input System과 조작 | `#1D4ED8` |
| `area:core` | 공용 값, 태그, 레이어, 기반 시스템 | `#E11D48` |
| `area:ui` | SETTINGS, 메뉴, HUD UI | `#DB2777` |
| `area:audio` | BGM, 효과음, 믹서 | `#0F766E` |
| `area:build` | Unity·패키지·빌드 설정 | `#475569` |

`priority:*`, `status:*`, `good first issue` 같은 운영 라벨은 이슈가 실제로 늘어난 뒤 필요성이 확인되면 추가한다.
